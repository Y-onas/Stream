> Current privacy policy: stream responses remain `Cache-Control: no-store`. The range engine bypasses IndexedDB for a no-store HEAD response and never writes no-store GET responses. Caching is disabled by default while device-storage controls are hidden. Worker revision5 clears/disables legacy cached media on activation, fencing old writes; normal-user logout clears/disables it too. The cache implementation remains available for explicit opt-in and cacheable responses. The older design notes below describe the retained implementation, not permission to cache private no-store streams.

# Browser segment cache

Native HTML video remains the playback engine. A same-origin module service worker intercepts only GET `/api/videos/:id/stream`. A normal video element does not read IndexedDB itself; the worker connects the two. MSE was not chosen because arbitrary original MKV/MOV/MP4 documents are not guaranteed to contain MSE-compatible fragments, and this module does not transcode or remux content.

The design follows the browser's [service-worker fetch event](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/fetch_event) model. Service workers require a secure context (localhost qualifies during development). If registration is unavailable, the native player uses the same network URL directly. Browser [storage quotas and eviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) are controlled by the browser; local settings cannot guarantee persistence.

For every logical video request, the worker obtains HEAD metadata from the real stream. A positive safe-integer size and a strong ETag are required for caching. The key combines the public video URL, ETag and exact aligned offset; document replacement cannot mix old and new bytes. HEAD failure or missing trustworthy metadata falls back to ordinary network behavior. This is not offline playback: metadata is revalidated online.

Ranges are inclusive. The worker splits them into fixed 1 MiB segments, loads existing exact segments from IndexedDB, and requests missing segments with Range and If-Range. Overlapping and partially cached ranges share those segments; only the requested intersection is emitted, in order. Each downloaded segment must have 206, the expected Content-Range, matching ETag and exact length before it is stored. A full-file 200 response to a part request is canceled without reading the full body. Body size is bounded while reading too.

ReadableStream backpressure drives sequential retrieval, with no app-level speculative prefetch. A request holds only bounded parts, not the whole requested range. Browser media buffering policies can still read ahead while playing; `preload="metadata"` avoids requesting a whole video simply on opening its page. There is no full-file download job. At most two network operations run at once in a worker, and simultaneous consumers share a missing segment. Cancellation aborts upstream work when no consumers still need it. A worker restart loses in-flight deduplication but preserves valid stored segments.

IndexedDB stores complete segments with stable video ID, ETag, start/end offsets, byte data and last-used time. Transactions serialize insertion and eviction. The retained budget is 128 MiB, with legacy configuration support from 32 to 512 MiB; those controls are hidden and caching starts disabled. Least-recently-used parts are removed to make room. Clearing or disabling caching increments a generation counter so pending writes cannot repopulate cleared data. Quota/permission/storage errors skip persistence and allow network playback; the player also offers an explicit retry with caching off.

No media segments are written to the server disk. The Go authentication session and optional small local artwork are separate from video caching. A thumbnail is an explicitly extracted still image, not a retained video range. Device storage is specific to the current browser profile and origin and may be evicted. Progress and saved IDs use localStorage, with graceful failure handling. Normal-user logout now clears/disables the segment cache. Profile collections are account-owned; resume keys are user-scoped. The Module3 cache code is retained for permitted future opt-in use.
